# Repository Instructions

- Do not run `cargo fmt` anywhere in this stack unless the user explicitly overrides this instruction. Keep edits narrowly formatted by hand to avoid broad formatting churn.
- Always use release-mode cargo (`cargo build --release`, `cargo test --release`) unless the user says otherwise, so `target/debug` artifacts do not accumulate.
- Delete any consumed patch or diff files after applying them, so stale artifacts do not confuse later work.
- Push as GitHub account `djienne` through the existing SSH key under `~/.ssh/`, selected by `~/.ssh/config` for `github.com`. Use command-scoped SSH URL/`core.sshCommand` overrides with `BatchMode=yes` and `StrictHostKeyChecking=yes`; keep the saved remote URL unchanged and verify remote HEAD matches local HEAD after pushing. Do not mention unrelated GitHub account identities.
- Starting live trading or running a live taker-handover test requires the user's direct decision. Keep the screener and dry runs collecting continuously until the user says to stop; preserve their existing data and state during maintenance.
- After implementing bot behavior/config changes from a plan, commit the validated changes, then rebuild and restart the dry run (`docker compose up -d --build dryrun` in `LIGHTER_ASTER_BOT/`). Restart a live bot (`run --mode live`, see `LIGHTER_ASTER_BOT/RUNBOOK.md`) only when one is running, and not if the user says not to.
- `run --mode live`, `taker run` without `--observe-only`, `close`, `probe aster-place-cancel`, `probe hl-hedge`, `probe hl-place-cancel`, and the `*-market`/`*-roundtrip` probes submit real orders. Routine validation uses unit/local-transport tests and the dry run (`run --mode dry-run`, RUNBOOK "Dry run"), which needs no credentials and submits nothing real.
- Venue `*.env` files and `runs/` stay local and ignored by git; check `git status --short` before each commit.
- For results, run the existing reports from the repository root before writing any analysis code: `python dryrun_summary.py` (one screen per dry-run market), `python screener_summary.py` (the screener's ranking; it runs the report in Docker), and for detail `combined_pnl.py`, `bot_stats.py` and `trade_history.py` (`--dry-run --market <M>`). If a question needs something they lack, extend the fitting script instead of writing a one-off.
- Websocket market data always uses a venue's fastest mode wherever one exists; check the venue's docs for every new subscription. Hyperliquid `l2Book` must carry `"fast": true` (5 levels a side every ~0.54 s instead of 20 every ~5.4 s, measured on HYPE 2026-09-28); the bot's live connector and dry-run feed share `connectors::hyperliquid::subscriptions`, and the SCREENER subscribes the same way. Aster uses `@depth20@100ms` (its fastest) with real-time `bookTicker` and `aggTrade`. Lighter has no speed option (`order_book` is batched every 50 ms).
